## Reconciliation with the earlier campaign

The earlier campaign (walking route, ~890 draws) measured at 3440: off 27.2-28.8 ms,
p1-p4 = 24.2 / 22.8 / 21.4 / 19.7 ms p50. This standing-run campaign reproduces **p4 exactly
(19.72 vs 19.7)**, p3 within +1.9 ms, but p2/p1/off come out +8 to +12 ms heavier, and 'off'
(35.4 ms p50) lands essentially ON p1 (36.7) instead of clearly above it. Deltas: p4 +0.0,
p3 +1.9, p2 +10.2, p1 +12.5, off +7-8 vs campaign. Both measurements are internally honest; the
difference concentrates in the protect/ipc term above. Which spot/build state it belongs to is a
separate measurement (see "next lever").

## Conclusions

1. **Cost of sharper, per step, at 3440x1440**: p4→p3 = +3.6 ms (19.72→23.29) for 2x the raster
   pixels; p3→p2 = +9.8 ms for +35% pixels (the protect term more than doubles); p2→p1 = +3.6 ms
   for +25% pixels; p1→off = −1.3 ms (native is slightly CHEAPER than p1: the FSR chain costs more
   than the extra fill but the protect term drops 24.1→16.7).
2. **Best fps-per-blur is p4** (19.72 ms, 48.9 fps) — but its stretch is 3x, which is exactly the
   blur the owner rejects. The first step up (p3, 2x stretch) buys the largest sharpness gain per
   millisecond (+2.0x pixels for +3.6 ms); p2 (1.7x) costs +9.8 ms and lands at 28.7 fps, below
   the 30-fps floor where the upscaler's temporal stability starts to suffer at 26-29 fps.
3. **60 fps at 3440x1440 is not in reach on any configuration in this curve**: the best case (p4)
   is 3.0 ms above 16.7 ms and its stage-A + b_busy alone sum to ~20.2 ms. 'off' native is 35.4.
   The measured micro-lever ceiling on this line was ~1-1.5 ms total and is closed.
4. **Motion blur** (game-side `effect_motion_blur`): p4 with it OFF measures +1.97 ms p50
   (21.69 vs 19.72) and −67 draws/frame (823 vs 890) — removing the game's own blur pass does NOT
   save time on this build; the guest post chain composition shifts by more than the pass costs.
   (Only the frame-time delta is measured; the visual contribution of the game's blur is not.)
5. **Next honest lever (a measurement, not a build)**: the protect/ipc term. Same standing route,
   preset 1, two runs: baseline against a run with the layer-trap machinery instrumented
   (BB_FRAME_TIMELINE=1 and the 'layer memory ms: traps set/cleared/republish' line) to split the
   24 ms into mprotect traffic vs write-fault handling on the bigger proxies — whatever dominates
   is the remaining lever, because the GPU's own execute time already saturates (off ≈ p1). Pair
   it with re-running the older campaign's walking route on today's build to reconcile the
   campaign's p1=24.2 with today's 36.7 (spot vs build state, one run each settles it).
