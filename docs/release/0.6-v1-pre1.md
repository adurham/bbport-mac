A **test build** of bbport for Mac 0.6, for people willing to try it and report back.
**Experimental.** The latest regular release is still 0.4-v1. No game files are included: you
need your own decrypted copy of Bloodborne merged with the 1.09 update.

**Install:** download the zip below, open it and drag **bbport.app** into Applications (replace
an older one: your settings and saves are kept). You need an Apple Silicon Mac with macOS 26 or
later, Rosetta 2 and the Command Line Tools (for Python 3). The app isn't notarised: the first
time, allow it in **System Settings ▸ Privacy & Security ▸ Open Anyway**. The
**[user guide](https://github.com/bmy/bbport-mac/blob/macos-native-0.6/docs/USER_GUIDE.md)**
has the details.

Everything below is new since **0.4-v1**: three upstream releases (bbport 0.5, 0.51 and 0.6 by
deadinside28) and the Mac port's own work in between.

## The Mac port

**Faster: the GPU work runs as native Apple Silicon code**
- The renderer, the shader translator and the Vulkan driver now run in a **process of their own,
  as native arm64 code**; only the game's own x86-64 code still runs under Rosetta 2. The two
  processes share the game's memory. This is the default; Developer ▸ *In-process GPU (Rosetta)*
  switches back to the old way.
- **Passes that draw nothing no longer cover the whole GPU**: they used to start at the largest
  possible area (16384×16384), which Apple's tile-based GPUs walk tile by tile; +15% in one
  measured spot.
- Less waiting between the threads that feed the GPU (the mapping table's lock, the MetalFX
  hand-over).

**Upscaling**
- **MetalFX**, Apple's temporal upscaler, alongside FSR 3.1 and TAA, in the game's own menu too
  (with an Ultra Quality preset). MetalFX now gets its work from a thread of its own, so the rest
  of the frame doesn't wait for it, and if MetalFX ever fails the game switches to FSR 3.1 by
  itself.

**Graphics driver**
- **A newer KosmicKrisp** (Mesa's Vulkan on Metal), the revision mainline shadPS4 ships:
  **geometry shaders are emulated**, so the effects that need them are drawn instead of skipped.
  `BB_GEOMETRY_SHADERS=0` in *Extra variables* skips them again if one looks wrong.
- The driver's memory no longer grows over a long session (pooled command buffers).
- Shaders read from the driver's on-disk cache are checked before use, so a damaged cache entry
  is recompiled instead of crashing.

**Display and memory**
- **Every aspect ratio**, 4:3 to 32:9 ultrawide, with more of the game shown at the sides (or
  above and below) instead of a stretched picture; the app offers each ratio's resolutions.
  *Auto* follows your display (16:10 on a MacBook). New installs start at **16:9, 1920×1080**,
  the PS4's own.
- **Direct memory sized to what the game draws**: about 5 GB (the PS4's own) while the game draws
  at 1080p or less before upscaling, more for larger scenes, up to 9 GB. A flat 9 GB made smaller
  Macs run out of GPU memory.
- The GPU memory budget follows Metal's limit for your Mac, less what the rest of the app uses.

**Crashes fixed**
- **Code 23**, two causes: an invalid vertex format the game sometimes writes (the Mac's driver
  took a path where it was fatal), and a very large upload of game data (seen during a visceral
  attack).

**Reports and safety**
- The log says more when something goes wrong: GPU waits over a second name what the GPU queue
  holds, slow MetalFX frames say where each side got to, and MetalFX's first frame is timed.
- Every upstream release and every dependency change gets two independent security reviews
  before it's built (pinned dependencies, the CI token, paths in logs); the native GPU process
  checks every message it gets from the game process.

## From bbport 0.5, 0.51 and 0.6 (deadinside28)

**New**
- **Settings in the game's own menu**: *System ▸ Display* and *Effects*, on the title screen and
  in the pause menu: output resolution, preset and sharpness, FPS counter, model detail and
  upscaler; chromatic aberration, depth of field, motion blur, SSAO, dynamic shadows. Effects now
  switch **without a restart**.
- **Frame rate through hooks**: above 30 FPS the game's main loop and the places tied to its
  30 FPS frame use the real frame time (body-part physics ran several times too fast at high
  frame rates; running fell to walking above ~90 FPS). **F3** (fn+F3 on a Mac keyboard) turns a
  30 FPS limit on and off while you play.
- **Keyboard and mouse**: mouse look that turns the game's camera directly, mouse buttons and the
  wheel as bindable keys, a default layout close to Dark Souls III, movement keys that ramp up
  like a stick, and **button prompts** for the device you're using (keyboard, Xbox or other
  pads; PlayStation icons with a PlayStation pad).
- The game's own **aspect ratio hooks** (the camera, the HUD anchored to the screen's edges, full
  screen fills), which the Mac's aspect ratios above build on.
- Fewer hitches: new pipelines compile in the background (geometry may appear a frame late
  meanwhile), and the shader caches are kept between sessions.
- **Every retail release** of Bloodborne with update 1.09 is accepted (US, EU, UK, JP, Asia and
  The Old Hunters editions); saves with The Old Hunters load. Only CUSA03173 has been tested on
  the Mac.
- *Quit game* from the overlay menu.

**Fixes** (among many)
- Laurence's cinematic above 30 FPS no longer hangs, and models no longer explode or go missing
  in it.
- Single frames shifted by half the screen or squeezed into a corner (bright or dark flashes).
- A crash when loading a save (two of the game's threads writing one command buffer).
- A loading hang at lamp travel; a crash when the game's per-frame command heap filled up.
- An empty character-creator preview.

**Not on the Mac**: online play, DLSS and FSR 4. The Mac keeps the 0.3 memory model (VRAM
copies), not 0.5–0.6's new one.

## Known issues

- **Short pauses while shaders compile**, mostly when an area loads; the first launch, and the
  first after this update (the new driver starts its caches again), shows a black window for a
  few minutes.
- **Busy scenes can drop below 60 FPS** at high resolutions: the translation to Metal still costs
  GPU time, mostly where the game's own copy routines interrupt rendering.
- **The in-game menu pointer** (mouse) doesn't work with the native GPU process yet; the keyboard
  and controllers drive the menus.
- **Tested on one Mac** so far (M5 Max).

## Please report

On the [Issues page](https://github.com/bmy/bbport-mac/issues): your Mac (model, chip, memory),
macOS version, what you did and what happened, with the log attached (**Help ▸ Show the Last
Run's Log**, right after quitting the game). Please don't report Mac problems to upstream bbport
or shadPS4.
